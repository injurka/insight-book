# Git Release Minor Workflow

Применяй этот скилл, когда пользователь просит сделать минорный релиз (minor release), выпустить минорную версию, увеличить минорную версию или обновить тег.

## Порядок действий

1. **Проверка нескоммиченных правок:**
   - Убедись, что находишься в корне проекта.
   - Проверь статус рабочей директории через `git status --porcelain`.
   - **Если есть нескоммиченные правки** (staged или unstaged изменения):
     Сначала примени скилл [git-commit](file:///home/injurka/my/insight-book/.agents/skills/git-commit/SKILL.md), чтобы закоммитить имеющиеся изменения по стандартам проекта (с проверкой линтером, typecheck и в формате Conventional Commits).

2. **Запуск скрипта релиза:**
   - Запусти скрипт для выпуска минорного релиза:
     ```bash
     bash .agents/skills/git-release-minor/scripts/release-minor.sh
     ```
   - Скрипт выполняет следующие действия:
     - Рассчитывает новую минорную версию на основе последнего тега `vX.Y.Z` (`vX.Y+1.0`).
     - Обновляет поле `"version"` в корневом `package.json`.
     - Если есть незапушенные локальные коммиты, обновляет последний коммит (`git commit --amend --no-edit`), включая в него обновление `package.json`.
     - Если незапушенных коммитов нет, создает новый релизный коммит (`chore(release): vX.Y.Z`).
     - Отправляет ветку в remote-репозиторий (`git push origin <branch>`).
     - Создает локальный аннотированный тег `vX.Y.Z` и отправляет его в remote (`git push origin vX.Y.Z`).

3. **Завершение:**
   - Сообщи пользователю об успешном создании нового тега и его отправке в репозиторий.
