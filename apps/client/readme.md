# Архитектура клиентского приложения (insight-book)

## Введение

Данный документ описывает архитектуру клиентского приложения **insight-book**, построенного на принципах **Feature-Sliced Design (FSD)**, **Vertical Slice Architecture (VSA)** и элементах **Domain-Driven Design (DDD)**.

Приложение представляет собой ридер книг с умными функциями изучения языков и анализа текста (интеграция с LLM, интервальное повторение по алгоритму FSRS, генерация и обработка карточек/словаря, проверка произношения, синтез речи TTS, офлайн-режим PWA).

Ключевая идея архитектуры заключается в **организации кодовой базы вокруг функциональных срезов (фич) и сущностей предметной области, а не по техническим типам файлов**.

---

## Ключевые принципы

1. **Слоевая структура (Layered Architecture)**: Код разделен на слои с четко определенной иерархией зависимостей (снизу вверх, от `01` к `06`).
2. **Вертикальные срезы (Vertical Slices / Features)**: Функциональность группируется по фичам. Весь код, относящийся к одной фиче (UI, состояние, модели), инкапсулируется локально.
3. **Низкая связанность (Low Coupling) и Высокая связность (High Cohesion)**: Модули максимально изолированы друг от друга и взаимодействуют либо через явный Public API (`index.ts`), либо через событийно-ориентированную шину (`AppEventBus`).
4. **Однонаправленный поток зависимостей**: Зависимости разрешены только в одном направлении — от верхних слоев к нижним.

---

## Структура проекта (`src/components`)

Директория `src/components` — ядро компонентной архитектуры. Числовой префикс каждой поддиректории определяет её уровень в иерархии и правила импорта.

### `01.kit` — UI Kit (Design System)

- **Назначение**: Самый низкий уровень, содержащий презентационные (Dumb/Presentational) атомарные UI-компоненты без бизнес-логики.
- **Примеры**: `kit-btn`, `kit-dialog`, `kit-input`, `kit-dropdown`, `kit-toast`, `kit-tooltip`, `kit-select`, `kit-tabs`, `kit-skeleton`, `kit-toggle`, `kit-checkbox`, `kit-view-switcher`.
- **Правило**: Компоненты этого слоя не могут импортировать ничего из слоев `02` и выше.

### `02.shared` — Общие компоненты (Widgets & UI Helpers)

- **Назначение**: Более сложные, но универсальные сервисные и UI-компоненты общей логики, не привязанные к конкретной бизнес-сущности.
- **Примеры**: `app-titlebar`, `activity-heatmap`, `hover-reveal-bg`, `page-loader`, `reload-prompt`, `toast-manager`.
- **Правило**: Могут импортировать только из `01.kit` и глобальных утилит `shared/*`.

### `03.domain` — Доменные сущности (Domain Model / Entities)

- **Назначение**: Инкапсулирует ключевую бизнес-логику предметной области (DDD).
- **Примеры**:
  - `entities/book.entity.ts`: Сущность книги (`BookEntity`), инкапсулирующая доменные правила (расчет процента прогресса, работа с обложкой и страницами).
  - `entities/flashcard.entity.ts`: Сущность флеш-карточки (`Flashcard`), инкапсулирующая алгоритм интервального повторения FSRS (`calculateNextReviewIntervals`).
- **Правило**: Могут импортировать из `01.kit` и `02.shared`.

### `04.features` — Функциональные блоки (Фичи)

- **Назначение**: Интерактивные "вертикальные срезы" пользовательских сценариев. Каждая фича инкапсулирует свою бизнес-логику, локальный store и UI.
- **Примеры**:
  - `analysis`: Анализ текста страницы или книги.
  - `auth`: Формы и логика авторизации/аутентификации.
  - `dict-word`: Взаимодействие со словом из словаря (добавление, карточки, переводы).
  - `global-actions`: Быстрые глобальные действия и хоткеи.
  - `limits`: Индикация и контроль пользовательских лимитов (токены/квоты).
  - `llm-chat`: Чат с ИИ-ассистентом по контексту книги.
  - `pronunciation-check`: Проверка произношения с записью голоса.
  - `quote-modal` & `quote-practice`: Сохранение цитат и тренировка по ним.
- **Правило**: Могут импортировать из `01.kit`, `02.shared`, `03.domain`. Фичи не должны напрямую зависеть друг от друга.

### `05.modules` — Модули приложения (Страницы и крупные блоки)

- **Назначение**: Композиционный слой (Smart Components), объединяющий фичи и доменные сущности для создания полноценных разделов приложения.
- **Примеры**:
  - `reader`: Читалка книг (поддержка текста, манги, выделений, TTS и панелей управления).
  - `library`: Библиотека пользователя (список книг, фильтрация, импорт/загрузка).
  - `dictionary`: Словарь и интервальные тренировки по карточкам.
  - `notebook`: Заметки, цитаты и сохраненные фрагменты.
  - `book-info`: Подробная информация о книге.
  - `settings`: Настройки приложения (темы, ключи LLM, профиль).
  - `onboarding`: Экран приветствия и первичной настройки.
- **Правило**: Могут импортировать все нижележащие слои (`01` - `04`).

### `06.layouts` — Слои представления (Шаблоны)

- **Назначение**: Определяет общую структуру и каркас страниц приложения.
- **Примеры**: `default` (стандартный шаблон с тайпбаром и навигацией).
- **Правило**: Могут использовать все нижележащие слои.

## Другие ключевые директории (`src/*`)

- **`assets`**: Глобальные стили, переменные тем (`global.scss`), шрифты и миксины.
- **`pages`**: Точки входа для Vue Router. Файлы здесь соответствуют URL-маршрутам и отображают компоненты из `05.modules`.
- **`workers`**: PWA и Service Worker (`workers/service/sw.ts`) на базе Workbox.
- **`shared`**: Глобальный не-компонентный код:
  - `composables`: Общие Vue-композиты (`useUmami`, `useAppWakeLock`, `useBackHandler`).
  - `events`: Шина событий (`AppEventBus`) для события-ориентированного взаимодействия между модулями.
  - `repositories`: Сетевой слой на основе **Repository Pattern** (`repos.book.list()`).
  - `services`: Сервисы приложения (IndexedDB / LocalForage, офлайн-кеширование, LLM, TTS, очередь фоновой синхронизации `book-sync.service.ts`).
  - `store`: Глобальные Pinia stores (`settings.store.ts`, `auth.store.ts`).
  - `types`: TypeScript типы, интерфейсы и DTO-модели.

---

## Управление состоянием и Поток данных

1. **Серверное состояние (Server State)**:
   Используется `@pinia/colada` (`useQuery`, `useMutation`). Данные из API автоматически кэшируются, инвалидируются и синхронизируются.

2. **Глобальное состояние (Global State)**:
   Используется классический Pinia (например, `settings.store.ts`, `auth.store.ts`).

3. **Сохранение состояния (Persisted State)**:
   Настройки и параметры пользователя сохраняются в local storage с помощью `useLocalStorage` из `@vueuse/core`.

4. **Событийно-ориентированная шина (Event Bus)**:
   Используется `AppEventBus` (`shared/events/app-event-bus.ts`) для слабой связности (Decoupling). Например, событие `DICTIONARY:WORD_SAVED` прослушивается читалом для обновления подсветки слов без прямой зависимости от модуля словаря.

---

## Сетевой слой и Архитектура репозиториев

* **Repository Pattern**: Работа с API абстрагирована в `shared/repositories`. Компоненты не вызывают `fetch`/`ofetch` напрямую, а используют методы репозиториев (`repos.book.list()`).
* **Dependency Injection (DI)**: Используются `provide/inject` и хук `useRepos()`, что упрощает тестирование и изолирует сетевую логику.
* **HTTP Client & Interceptors**: Настроен клиент `ofetch` (`api.service.ts`) с интерцепторами для JWT-токенов (`Authorization: Bearer`), настроек LLM и централизованной обработки ошибок.

---

## Кэширование и Офлайн-архитектура (Offline First)

* **Service Worker & PWA**: Кастомный Service Worker (`workers/service/sw.ts`) с Workbox-стратегиями (`CacheFirst`, `StaleWhileRevalidate`, `NetworkFirst`).
* **Уровни кэширования**:
  * *IndexedDB / LocalForage*: Кэширование книг, страниц, словарей, TTS-аудио и ответов LLM для полноценной работы без интернета.
  * *Background Sync*: Сервис `book-sync.service.ts` батчами предзагружает страницы, анализирует их и сохраняет в локальную базу.

---

## Взаимодействие с платформой и Устройствами

* **Web и WebView (Tauri)**: Проверка окружения через `isTauri()` с динамической инициализацией нативных сервисов (Tauri auto-updater).
* **Browser & Platform APIs**: Использование `MediaRecorder` для записи речи, `window.speechSynthesis` для озвучки, `navigator.storage` для контроля квоты памяти.
